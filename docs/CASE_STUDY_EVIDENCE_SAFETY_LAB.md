# Case Study｜Evidence & Safety Lab

## 产品问题

大量医疗 AI Demo 证明“模型能回答”，却没有回答产品团队真正需要的五个问题：谁使用、用于什么决策、证据是否足够、什么时候必须停止、谁承担最终复核责任。

## 目标用户与业务价值

目标用户是医疗 AI 产品经理、临床研究者、数据科学家和质量/安全角色。产品将散落在 PRD、模型报告和评审会议中的风险判断整理为可下载、可复核的评测记录，目标是降低前期沟通成本并提前暴露不可上线的用途或数据输入。

## 我的关键决策

1. 先定义 intended use，再讨论模型性能；
2. 把患者级数据和自动诊疗设置为原型停止条件；
3. 将证据缺口直接转换为评估任务，而不是给出模糊风险分；
4. 所有高风险结果保留人工复核与版本记录；
5. 公开 Demo 只使用合成或汇总信息。

## 当前产品闭环

输入场景 → 安全准入卡 → 证据缺口 → 动态评估计划 → Markdown 报告导出 → 可用性测试记录 → 反馈台账 → Claim Checker。

## 可检查证据

- 在线可运行 Demo；
- 3 个预设业务场景；
- 9 项自动测试；
- 敏感信息拦截；
- 本地可用性测试记录；
- 可下载审计式 Markdown 报告；
- 公开反馈协议与结果报告模板。

## 当前边界

目前已完成的是软件产品与规则测试。真实用户结果、临床有效性、监管状态、医院部署和商业收益均未验证，必须在获得真实证据后再更新。

## 下一阶段准入条件

完成 5–8 名目标角色的第一轮可用性测试；关闭或明确接受所有 S1 问题；公开样本构成、任务完成率、用时和未解决问题，再决定下一版本范围。
