# Evidence & Safety Lab v0.1 — 公开反馈方案

## 测试目标

验证用户能否在不接触真实患者数据的前提下，正确完成预期用途定义、证据缺口识别和安全边界判断。当前阶段只评估产品流程、可理解性和信任校准，不评估临床有效性。

## 允许的数据

- Demo 内置合成场景；
- 测试者自行编写的完全虚构场景；
- 不含小样本敏感单元格的汇总描述。

禁止输入患者级记录、身份信息、病历自由文本、日期、影像、声音、EEG、基因数据或其他可识别健康数据。

## 第一轮任务

1. 使用默认合成场景生成证据卡。
2. 将数据级别改为“患者级/可识别数据”，确认系统进入 `STOP / L5`。
3. 将决策角色改为“自动诊疗/处置”，确认系统解释禁止原因。
4. 恢复为合成数据，补全四项证据，判断结果是否会让用户误以为已经临床验证。
5. 提交结构化 GitHub Issue，记录角色、任务、严重度和建议。

## 指标

- 核心任务完成率；
- 首次完成时间；
- 安全关键误解数量；
- STOP 状态识别率；
- 证据缺口识别率；
- SUS（后续受控测试）；
- 最严重未解决问题及其版本归属。

## 准入条件

v0.2 前至少完成 5 名专业角色的测试；所有 S1 问题必须关闭或记录停止发布决定。测试通过仅表示交互和声明边界得到改进，不代表临床安全、有效性、合规或监管授权。

**Not for patient care or live clinical use.**
